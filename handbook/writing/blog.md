# Blog 작성법

대상: `src/content/posts/<id>.md`. 파일 이름이 URL이 된다. 본문은 Markdown이며 Svelte/React 코드를 넣지 않는다.

## 메타데이터

```yaml
---
title: 실제 주제를 나타내는 짧은 제목
date: "2026-01-01"
draft: true
---
```

draft를 지우거나 false로 바꾸면 공개된다. 초안은 글 목록뿐 아니라 상세 페이지, RSS, 사이트맵에서도 제외된다. 날짜는 실제 발행일로 바꾸며 파일 이름에서 추정하지 않는다.

## 유형별 골격

### 사용 후기 / 기술 설명

표본: `20230326.md`, `20240302.md`.

```markdown
[시작하게 된 실제 필요나 사용 기간].

## [구체적인 문제 또는 설정]

[시도한 방법과 출처].

## [사용하면서 바꾼 점]

[관찰한 문제]. [선택한 방법과 이유].

[현재의 평가와 아직 남은 한계].
```

개인적인 효용을 보편적인 최고의 방법으로 표현하지 않는다.

### 기술 소고

표본: `20251109.md`.

```markdown
이 글은 [대상]에 대해 [제공된 관점]을 정리한 것이다.

## [핵심 개념/경계]

[개념과 전제].
[구체적인 사례].
다만 [예외나 비용].
[조건이 붙은 결론].
```

질문형 전환은 논리적 필요가 있을 때 쓴다. 무조건 찬반을 균등 배치하지 않는다.

### 독서 정리

표본: `20240419.md`, `20230504.md`.
책/저자/판본을 확인하고 장별 요약 또는 주제별 메모를 쓴다. 원문 인용은 인용부호와 출처로 구분한다. 작성자의 보충 의견은 별도 문단으로 분리한다. 원문을 확인하지 않은 페이지 번호나 직접 인용을 만들지 않는다.

### 여행 / 가족 / 짧은 기록

표본: `20240328.md`, `20240408.md`, `20190418.md`.

```markdown
[누구와 언제 어디에 갔는지, 제공된 사실만].

![실제로 보이는 장면 설명](/image/날짜/사진.jpg)
_짧은 캡션_

[사진과 연결되는 관찰이나 실제 경험].
```

시간 순서와 사진 중심으로 쓴다. 음식, 동선, 가족의 작은 행동이 소재가 된다. 억지 교훈/여행 추천/총평을 붙이지 않는다. 한 문장으로 끝나도 좋다. 농담과 감탄은 실제 메모에 있을 때만 살린다.

## 미디어와 발행

- 이미지는 `public/image/`에 두고 `/image/...`로 링크한다. 대체 텍스트는 사진을 보고 작성한다.
- 코드는 언어가 표시된 fenced block을 사용한다.
- 동영상은 controls, iframe은 title을 제공한다. 외부 파노라마는 네트워크와 공급자 정책의 영향을 받는다.
- 새 글에서 문단 간격을 만들기 위한 연속 br은 쓰지 않는다. 발행된 글의 줄바꿈은 별도 편집 요청 없이 변경하지 않는다.
- 제목/날짜 중복 출력은 하지 않는다. 레이아웃이 제공한다.

검수: 사실과 의견/인용이 분리되는가? 원문 목소리보다 템플릿이 먼저 보이지 않는가? 초안의 미확정 대괄호가 남지 않았는가? 모바일 코드/사진과 링크를 확인했는가?
